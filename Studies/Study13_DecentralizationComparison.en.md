# 1. Introduction – Decentralization as a multi-layer concept

Stablecoins differ not only in code but in:

- who controls parameters,  
- who controls collateral,  
- who controls price oracles,  
- how supply is managed,  
- how regulatory exposure propagates into the system,  
- how many human decisions affect the protocol.

“Decentralization” therefore has multiple layers:

> A system can be technically decentralized but economically centralized — or the opposite.

ProjectUSD is the first model that achieves **full decentralization across all layers simultaneously**.

# 2. Evaluation framework: The six dimensions of stablecoin decentralization

We use the following dimensions:

1. **Governance control**  
   – Can any team, DAO or multisig modify key parameters?

2. **Oracle dependency**  
   – Is value anchored to an external asset like USD?

3. **Collateral centralization**  
   – Are custodial assets held by institutions?

4. **Protocol mutability**  
   – Can the code be changed, paused or upgraded?

5. **Manipulation attack surface**  
   – TWAP manipulation, governance capture, bridge failures.

6. **End-to-end decentralization**  
   – How many steps require human intervention?

Using this matrix, we compare all major systems.

# 3. System analysis: MakerDAO / DAI

## 3.1 Governance
- highly governance-driven  
- MKR holders control all key parameters  
- large holders have disproportionate power → **oligopoly risk**

## 3.2 Oracle
- DAI depends heavily on USD price feeds  
→ the peg is externally defined

## 3.3 Collateral
Today the majority is:

- USDC  
- USDP  
- U.S. Treasuries via RWAs  

→ **strong centralization**

## 3.4 Systemic risk
- exposure to banks and regulators  
- MakerDAO can freeze, change or reconfigure DAI at any time

**Conclusion:**  
DAI is a **partially decentralized USD wrapper**, not an autonomous system.

---

# 4. System analysis: GHO (Aave)

## 4.1 Governance
- fully governed by Aave DAO  
- minting parameters, facilitators, debt ceilings → governance-operated

## 4.2 Oracle
- hard USD peg → external oracle dependency

## 4.3 Collateral
- depends on Aave vaults, many of which use centralized stablecoins  
→ indirect centralization

## 4.4 Systemic risk
- similar governance vulnerabilities as Maker  
- external market dependence

**Conclusion:**  
GHO is **heavily governance-centralized** and USD-dependent.

---

# 5. System analysis: USDe (Ethena)

## 5.1 Governance
- fully centralized control  
- all parameters adjustable  
- minting rights controlled by a company

## 5.2 Oracle
- strict USD peg  
- oracle dependency unavoidable

## 5.3 Collateral
- hedged derivatives stored on centralized exchanges (CEX)  
- high counterparty exposure  
→ **extremely centralized**

## 5.4 Systemic risk
- CEX risk  
- hedge failure  
- regulatory pressure  
- dependency on institutional liquidity

**Conclusion:**  
USDe is a **fully centralized synthetic USD product**.

# 6. System analysis: Centralized stablecoins (USDC, USDT)

## 6.1 Governance
- corporate entities with full control

## 6.2 Oracle

## 6.3 Collateral
- U.S. treasury bills

- cash reserves  

→ **complete central custody**

## 6.4 Systemic risk

- regulatory capture  
- banking counterparty failures

**Conclusion:**  
USDC/USDT are **tokenized money market funds**, fully centralized.
